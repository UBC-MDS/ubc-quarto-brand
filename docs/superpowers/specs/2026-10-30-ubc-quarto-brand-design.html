2  ubc-quarto-brand: design spec

Status: spec approved 2026-10-30 · small project, building on main (Q&A 29)

Kickoff’s questions and Dan’s answers are in 2026-10-30-ubc-quarto-brand-qa.md; each decision below cites its item there as (Q&A N).

2.1 Goal

A Quarto extension that gives any UBC course book the brand DSCI 521’s book was built with, so books stop copying styles from one another (Q&A 1, 18). A book adopts it with quarto add UBC-MDS/ubc-quarto-brand@vX.Y.Z and one line, format: ubc-html. The repository also holds a test book that renders every part of the brand, deployed as the live demo with the project docs (Q&A 3, 10).

The first book to adopt it is reproducible-and-trustworthy-workflows-for-data-science, in its own PR after v0.1.0 (Q&A 1, 24). DSCI 521 follows later, tracked in UBC-MDS/DSCI_521_platforms-dsci_book#35.

2.3 Design

2.3.1 The extension

One extension, ubc, in _extensions/ubc/ (Q&A 18). It contributes two things:

  • The brand, through metadata: project: brand: brand.yml. Quarto merges it into any project with the extension installed, whatever its format, so colours, fonts and dark mode apply even to a plain format: html page.
  • A ubc-html format with the theme layers (light: [brand, styles.scss], dark: [brand, styles.scss, styles-dark.scss]), the filters (code-labels.lua, custom-callout, quizdown), include-after-body: quizdown-theme.html, and the four custom callout types.

A format cannot carry the brand on its own: its brand theme layer means the project’s brand, and 521’s styles.scss needs the $brand-* variables that only the brand defines. A prototype rendered exactly this setup on Quarto 1.11.6, for a book and for a website (Q&A 18).

2.3.2 What a book can change

From the prototype (Q&A 18):

  • Add styles with an extra theme layer, light and dark as separate lists: format: ubc-html: theme: light: [extra.scss] dark: [extra.scss]. The layer comes after the extension’s, and $brand-* names work in it. A plain list (theme: [extra.scss]) crashes Quarto.
  • Add or recolour callout types with its own custom-callout: keys, which deep-merge over the extension’s (Q&A 19).
  • Turn on the MDS logo by pointing its sidebar or navbar logo at the bundled file (Q&A 16).
  • Not replace the brand piecemeal: a book’s own _brand.yml is silently ignored, and a top-level brand: replaces the whole brand, so it must define every colour the styles use.

2.3.3 The test book

The repository root is a Quarto book that renders with format: ubc-html, next to _extensions/ubc/ (Q&A 22, 23):

  • Home: the README.
  • Conventions: DSCI 521’s lectures/0-conventions.qmd almost as-is (Q&A 15): text, every listing kind, executed R and Python cells (Q&A 13), callouts, quizzes, tables, math, figures and tabsets. Only its links into other 521 chapters change.
  • Callouts: Quarto’s five built-ins (note, tip, important, warning, caution), plain and titled, the four custom types, and two exercises in a row for the numbering (Q&A 19).
  • Using it in a book: installing, the format line, the logo, extra styles, extra callouts, and the limits above.
  • Where it comes from: every file’s DSCI 521 original, linked at 991bae89cba9, and what changed (Q&A 21).
  • The project: the spec, the plan, the Q&A pages, the changelog and AGENTS.md, rendered from where they live.

tests/website/ is a one-page website project: a callout, a bash listing and a quiz. make copies the extension into it, git-ignored, before rendering it in CI (Q&A 10, 22).

Executed cells run through knitr, with Python through reticulate from the uv venv, as in 521. R needs knitr, rmarkdown and reticulate (renv); Python needs matplotlib (uv).

2.3.4 CI and delivery

  • pr.yml, on every pull request event: make check, then pr-preview-action deploys the rendered book to gh-pages under pr-preview/pr-<N>/ and comments the link, or removes the preview when the PR closes. Runs are grouped per PR and a newer event cancels an older run, so a merge mid-build leaves no stray preview (Q&A 11, 24).
  • publish.yml, on a push to main: the same build, then github-pages-deploy-action deploys the book to gh-pages with clean-exclude: pr-preview and force: false, so previews and the branch’s .nojekyll survive (Q&A 24).
  • make check: renders the test book and the website check, failing on any Quarto warning or unresolved link; runs tests/check-render.sh over the rendered HTML (the brand’s colours, both stylesheets, the labels, the callouts’ glyphs and colours, the counters, the quiz assets); runs lychee offline, actionlint and gitleaks.
  • Rulings: Ubuntu runner, Quarto 1.11.6 pinned and quarto-required: ">=1.11.0", Python 3.14, every third-party action pinned by commit SHA (Q&A 24).
  • Releases: a PR bumps version: in _extension.yml and adds a CHANGELOG.md entry; Dan tags vX.Y.Z after merging it (Q&A 17).
  • Straight to main: the agent commits and pushes to main; Dan reviews the extension in the adopting book’s PR, with its preview (Q&A 29). pr.yml serves anyone who opens a PR here later.

2.5 Open items and risks

  • Vendored dependencies: custom-callout (0.0.1-dev.3) and quizdown are copies; updating them is a manual PR.
  • Quizdown loads on every page, quiz or not, as in DSCI 521 (Q&A 12).
  • A partial brand override isn’t possible (see What a book can change); the how-to page says so.
  • Fork PRs get no preview: their token can’t write to the repository.
  • [Dan] settings: Pages from the gh-pages branch (after the first publish creates it), read and write workflow permissions, a ruleset on main.
  • plan-driven-development’s hooks and leak check aren’t built yet: every push of build follows make leaks.
